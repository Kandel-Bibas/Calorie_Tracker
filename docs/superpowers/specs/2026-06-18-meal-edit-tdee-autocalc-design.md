# Spec: Meal Edit, TDEE Auto-Calc, Meal Name Fix, Activity Level Migration

**Date:** 2026-06-18
**Branch:** `feat/calorie-tracker-v1`
**Status:** Approved

---

## 1. Overview

Four improvements to the iOS Calorie Tracker app:

1. **Meal name bug** — every saved meal shows "Lunch" because `mealType` is hardcoded.
2. **Meal edit** — users cannot tap a saved meal to view or edit it.
3. **TDEE auto-calc** — calories and macros must be entered manually; they should be calculated automatically from body stats and goal parameters.
4. **Activity level migration** — activity level lives in Profile; it belongs in Goals & Targets and should be stored on the `goals` table.

All changes are iOS-client-only except for one additive DB migration (no RLS change).

---

## 2. Meal Name Bug Fix

**Root cause:** `LogView.swift:350` hardcodes `mealType: "lunch"` for every saved meal.

**Fix:** Replace with `mealType: mealLabel.isEmpty ? nil : mealLabel`.

`TodayView.mealsSection` already renders `meal.mealType?.capitalized ?? "Meal"`, so the correct AI-generated label (e.g. "Chicken Rice Bowl") will display immediately after this one-line fix.

## 4. Meal Edit

### 4.1 Goal

Tapping any meal row in `TodayView` opens a sheet showing the full `MealReviewView` pre-populated with the meal's existing data. The user can rename the meal, edit item names/grams, add or remove items, then save. The save path updates the existing DB row rather than creating a new one.

### 4.2 New `MealEditView.swift`

Thin wrapper view. Receives a `Meal` value. On `task { }`:
- Fetches items via `SupabaseManager.fetchMealItems(mealId:)` (already exists).
- Converts each `MealItem` → `FoodItem` (absolute macros → per-100 g).
- Sets `mealLabel = meal.mealType ?? ""` and `mealNotes = meal.voiceTranscript ?? ""`.

Renders `MealReviewView` with the loaded state; shows a `ProgressView` while loading.

**`MealItem → FoodItem` conversion** (guard `grams > 0` to avoid divide-by-zero):
```
kcalPer100g    = item.kcal / item.grams * 100
proteinPer100g = item.proteinG.map { $0 / item.grams * 100 }
carbPer100g    = item.carbG.map    { $0 / item.grams * 100 }
fatPer100g     = item.fatG.map     { $0 / item.grams * 100 }
```

On "Save Log":
- Recomputes totals from edited `[FoodItem]`.
- Calls `SupabaseManager.updateMeal(meal:, items:)`.
- Dismisses on success; shows inline error on failure.

On "Re-record": dismisses without saving.

### 4.3 New `SupabaseManager.updateMeal(meal: Meal, items: [MealItem])`

Three-step operation (no transaction support in the Supabase Swift SDK; failures are surfaced as thrown errors):

1. UPDATE `meals` row — fields: `meal_type`, `total_kcal`, `total_protein_g`, `total_carb_g`, `total_fat_g`, `edited_at`.
2. DELETE all `meal_items` where `meal_id = meal.id`.
3. Batch INSERT new `meal_items` (loop, same as `insertMeal`).

Uses a local `Encodable` struct for the UPDATE payload to avoid encoding read-only `id`/`user_id`/`consumed_at`.

### 4.4 `TodayView` changes

Each meal row in `mealsSection` becomes a `Button` that sets `@State private var editingMeal: Meal?`. A `.sheet(item: $editingMeal)` presents `MealEditView`. After the sheet dismisses, `TodayView` refreshes its data via `await loadData()`.

## 5. TDEE Auto-Calc + Activity Level on Goals

### 5.1 DB Migration — `db/migrations/0001_goals_activity_level.sql`

```sql
ALTER TABLE goals
  ADD COLUMN activity_level text DEFAULT 'sedentary';

ALTER TABLE goals
  ADD CONSTRAINT goals_al_chk
  CHECK (activity_level IN ('sedentary','light','moderate','active','very_active'));
```

Existing rows get `'sedentary'` as the default. No RLS change needed (existing `goals` policies cover all columns).

### 5.2 `Goal` model update (`Models.swift`)

Add field:
```swift
var activityLevel: String?  // CodingKey: "activity_level"
```

Update both the `init(from decoder:)` and the memberwise `init` accordingly.

### 5.3 New `TDEECalculator.swift`

Pure struct — no SwiftUI, no HealthKit, fully unit-testable.

```
Input:
  sex: String           ("male" | "female" | "prefer_not" | nil → female formula)
  currentWeightKg: Double
  heightCm: Int
  birthYear: Int        (age = currentYear - birthYear)
  activityLevel: String
  intent: String        ("lose" | "gain" | "maintain" | "track")
  targetWeightKg: Double?
  pace: String          ("easy" | "steady" | "aggressive")

Output: (dailyKcal: Int, proteinG: Int, carbG: Int, fatG: Int)
```

**Algorithm:**

1. **BMR** — Mifflin-St. Jeor:
   - Male:   `10W + 6.25H − 5A + 5`
   - Female/other: `10W + 6.25H − 5A − 161`

2. **TDEE** = BMR × activity multiplier:
   | Level | Multiplier |
   |---|---|
   | sedentary | 1.2 |
   | light | 1.375 |
   | moderate | 1.55 |
   | active | 1.725 |
   | very_active | 1.9 |

3. **Target kcal** = TDEE ± pace delta:
   | Intent | easy | steady | aggressive |
   |---|---|---|---|
   | lose | −250 | −500 | −750 |
   | gain | +250 | +500 | +750 |
   | maintain / track | 0 | 0 | 0 |
   - Floor: 1200 kcal/day.

4. **Macros:**
   - `proteinG = max(Int(1.6 × currentWeightKg), Int(Double(targetKcal) × 0.25 / 4))`
   - `fatG = Int(Double(targetKcal) × 0.25 / 9)`
   - `carbG = Int((Double(targetKcal) − Double(proteinG) × 4 − Double(fatG) × 9) / 4)`, clamped to ≥ 0.

**Missing-input handling:** if `heightCm == 0` or `birthYear == 0`, the function returns `nil` so the UI can show "Complete your profile (height, birth year) to use auto-calc."

### 5.4 `GoalsEditView` changes

- Add `@State private var activityLevel: String = "sedentary"` and a `Picker`.
- Load `activityLevel` from the active goal in `loadHistory()` (falls back to `currentProfile?.activityLevel ?? "sedentary"`).
- Add a **"Calculate"** button in the "Update Goals" section. On tap:
  1. Fetches latest weight from Supabase (`fetchWeights(since:)`, take `.first`). Shows "No weight logged — log a weight first" if empty.
  2. Reads `heightCm`, `birthYear`, `sex` from `currentProfile`. Shows "Complete your profile (height, birth year) to use auto-calc" if missing.
  3. Calls `TDEECalculator.calculate(...)`.
  4. Fills `dailyKcalString`, `proteinString`, `carbString`, `fatString` with the results (user can still edit before saving).
- `updateGoal()` passes `activityLevel` when constructing the `Goal`.

### 5.5 `ProfileEditView` changes

Remove the `activityLevel` picker and its associated `@State`. The `save()` function still carries `current?.activityLevel` forward in the upsert (read-only passthrough) so existing values aren't clobbered.
